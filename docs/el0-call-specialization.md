# Analysis-based direct returns

The latest [runtime optimization](el0-runtime-optimization.md) and immutable-page
bitmap keep these call optimizations and reduce runtime to **6,177,120 (2.0311:1)**.
The measurements below are the call-analysis baseline.

The preceding saved-frame extension reduced runtime instructions to
**11,742,027 (3.8610:1)**. The measured workload now executes **13,240 returns**
as direct branches. The original leaf-only pass is retained below as a baseline.

## Partial leaf prefixes

The latest [measured extension](el0-runtime-optimization.md#partial-leaf-returns)
executes **19,378 returns as direct branches**, up from 13,240. It copies a
bounded X30-preserving prefix of a larger function and rejoins original code
before calls, X30 changes, gateways or unsupported effects. Only direct BL
entries use these private copies. Unproven paths and all original indirect
entries retain the existing checks; partial proofs cannot summarize callees.
The observation hook retains its checks while its original BL enters a proven
callee copy.

Every earlier copy remains. New exports add 1,838 partial call copies across
444 functions and one observation-hook call, for 3,348 root and 178 nested
copies. The version-3 proof records partial bodies and every original-code
exit. The total copy budget remains 100,000 source instructions; the image
uses 99,997. Nineteen analysis/execution tests pass, including 144 executable
fast-return/fallback cases and the preceding nested-call fixture. Full replay
and the complete original-PC index audit pass too.

## Saved frames and nested calls

The analysis now tracks symbolic entry registers, exact SP-relative addresses
and stored stack values through the reachable CFG. A load can restore X30 only
from an exactly matching saved value. CFG joins retain only facts established
on every incoming path. Overlapping stores invalidate saved slots; stores
through unknown pointers invalidate all remembered stack values.

Callee summaries describe actual register results and memory writes, without
assuming ABI register preservation or that argument pointers cannot alias the
stack. Summaries include the below-SP scratch stores generated by inline
system helpers. New frame summaries require balanced SP at return and the original
entry X30. It handles functions up to 64 source instructions and call trees
up to three nested call edges, retaining the 100,000-word total copy budget.
Recursive call cycles, unsupported gateways and unknown effects that prevent
restoration remain unoptimized.

Nested BL instructions preserve their original return-PC value in X30 and
enter a private child copy. Its direct return targets the continuation inside
the parent copy. Root copies return to the original caller. This avoids losing
the specialization when a nested call returns. Original indirect entries and
their checked context resumes remain intact.

The export contains **1,509 root call copies** (433 more than before) and
**178 nested copies**, totaling 31,512 copied source instructions across 439
functions. The version-2 [proof artifact](../build/el0-call-tree-20261114a/call-specialization.json)
records each context, parent, continuation, source instruction and nested depth.
Manifests distinguish `specialized_root_calls` and `specialized_nested_calls`.

## Initial leaf-only pass

The pretranslated exporter now specializes direct calls to proven leaf
functions. Each selected call enters a private copy whose `RET X30`
instructions become direct branches to that caller's continuation. There is
no target comparison, index lookup or return gateway in those copies.

The original function and every original-PC index entry remain available for
indirect calls, entry into the middle of a function and unspecialized callers.
This is a static proof for the private copies, without assuming all callers of
the original function are known.

## Construction proof

[`el0_call_analysis.py`](../tools/el0_call_analysis.py) follows both sides of
conditional branches and internal loops from the actual function entry. It
requires a closed reachable CFG of at most 32 original instructions:

- Every reachable instruction preserves X30. Loads into X30, writeback through
  X30, arithmetic destinations and unsupported implicit modifications reject
  the copy. Storing X30 without changing it remains allowed.
- The only exits are `RET X30`. Nested calls, tail calls outside the function,
  other indirect branches and returns through other registers reject it.
- Ordinary operations already admitted as native remain their original
  instructions. System operations must have a complete inline shadow-state
  implementation. Context gateways, fault adapters, exclusive groups, syscall
  instructions and unsupported metadata reject it.
- Only a direct BL instruction targeting the proven entry can enter a copy.
  The original X30 value remains the original caller PC plus four. Copies are
  absent from guest-PC indices and context-resume tables.

ADR/ADRP constants retain their original-PC values, internal branches are
relocated within the copy, and all memory/shadow side effects remain live.
No recorded branch sequence, return target or future syscall result is used.
The exporter limits total copied source instructions to 100,000.

This export selects **1,076 call sites across 330 functions**, copying 15,395
source instructions. Its [proof artifact](../build/el0-call-specialized-20261114a/call-specialization.json)
records every source instruction and call/continuation pair. New manifests
record `specialized_calls` and `specialized_source_words`.

**10,407 executed returns** now use one native direct branch. Runtime decreases
by **220,836 instructions (1.84%)**; total instruction executions decrease by
**210,429 (1.41%)**. The difference is the return branches now counted as native
kernel payload. Copied inline system operations also omit an unnecessary
branch to their next instruction. Source-operation accounting includes copies
under their original PCs; the kernel denominator remains unchanged.

Whole-ELF execution is 14,892,427 instructions. The ELF grows by only 77,640
bytes to 159,100,792 bytes. These are instruction/size measurements; processor
cycles and instruction-cache effects remain unmeasured.

The measured workload matches all **2,272 events**, **nine ordered counter
inputs** and **92 UART bytes**, with 4,664 gateways, zero hardware exceptions,
no EL1 runtime service and no host calls before completion. Initial RAM and
hardware tables remain embedded and no external page-table image is loaded.

The **0.20:1 ceiling** and **0.10:1 target** remain unmet. General function-pointer
calls and non-leaf or unresolved returns still use the checked index. Broader
elimination needs proofs for immutable target sets, tail-call paths, and saved
link-register values across nested calls.

## Verification

The analysis tests cover multiple returns, internal loops, escaping branches,
missing instructions, LR loads/writeback, preserved LR stores, metadata,
gateway/exclusive exclusions, direct-entry restrictions and size limits.
The profiler fixture verifies that clone labels and direct branches preserve
source/native attribution without changing loaded code. The complete PC-index
audit also passes on this ELF: all 467,872 original context targets and holes
remain intact and the index is read-only.

New pretranslated exports apply this pass automatically; use the existing
[build commands](el0-pretranslated-memory.md#build-and-verify).

```sh
python3 -m unittest discover -s tests -p test_el0_call_analysis.py -v
python3 -m unittest discover -s tests -p test_el0_instruction_profile.py -v
OSREC_EL0_INDEXED_IMAGE=build/el0-call-specialized-20261114a PYTHONPATH=tests \
  python3 -m unittest test_el0_indirect_cache.IndexedImage -v
```
